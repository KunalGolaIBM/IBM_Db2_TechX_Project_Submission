Checking server…

Delhi · 34 monitors · 1 Sep – 31 Dec 2025

On 338 station-days, a dashboard average still printed an AQI. CPCB's own rules say there was none.

AQI Truth re-checks every monitor-hour inside IBM Db2, applies the CPCB method as stored procedures, and refuses when the data can't support a number. IBM Granite only explains verdicts and turns questions into read-only SQL. It never decides.

Ask the audit

Granite writes one SQL query. Code checks it. Db2 runs it as AQREADER, a user that can only read two audited views, so the box can't change or leak anything else.

04

How a verdict is made

Everything a visitor sees is computed by SQL in Db2. The model sits outside the decision path.

IngestOpenAQ archive

CPCB · DPCC · IITM · IMD monitors, 15-minute rows, CC BY 4.0

Db2AQ.READING

MERGE upsert · range-partitioned by month · system-period temporal (revisions stay queryable)

Db2BUILD_HOURLY

window functions find stuck runs and impossible jumps

Db2COMPUTE_AQI_AUDITED

SQL PL: 16-hour rule, 8-hour O₃/CO, 3 pollutants incl. a PM, CPCB breakpoints

Db2Verdict + evidence ledger

append-only, enforced by triggers · VECTOR search over rule texts

GraniteExplain · Ask

numbers and words checked by code · SQL run as a read-only user

  • Verifiable receiptsEvery verdict gets a SHA-256 receipt of the exact readings and rules it judged, chained to the one before. AQ.VERIFY_RECEIPT replays the inputs FOR SYSTEM_TIME AS OF the issue time.
  • Row access controlA row permission on AQ.VERDICT hides the out-of-scope monitor from every ID without the AQAUDITOR role.
  • Least privilegeThe app's ID can only SELECT and INSERT, the question box's ID can read two views, and even the owner gets SQLSTATE 75001 on an edit.
  • Checked by one commandpython scripts/db2_evidence.py runs 25 Db2 claims against the live database and records each answer. See the results
