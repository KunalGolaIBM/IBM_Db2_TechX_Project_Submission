The care loop

Personal preferences flow into contextual analysis, trigger evaluation, and a humanized companion. Relational history is stored in local IBM Db2.

STEP 01 · CONTEXT

User Profile & Health Preferences Ingestion

The experience begins with what a person chooses to share: preferred name, local time zone, check-in preference, and their own reminder details.

DESIGN PRINCIPLE

Ask only for what the companion needs. Keep preferences editable and connected to the person’s session.

CONTEXT · 02 / 06
STEP 02 · SYNC

Interactive Profile & Preference Sync

Onboarding writes preferences to the application API, which stores the profile and user-authored routines in the local Db2 database.

PERSON→AETHEL API→IBM Db2
PRIVATE BY SESSION

The signed browser session scopes profile, reminders, and conversation history.

PREFERENCE SYNC · 03 / 06
STEP 03 · REASONING

Contextual Care Analyzer

LangGraph coordinates contextual checks and LangChain supports the chat response using the current message and recent conversation history.

PROFILE + HISTORY→LANGGRAPH STATE→LANGCHAIN RESPONSE
BOUNDED SUPPORT

The agent does not diagnose, select medicines, prescribe doses, or claim a reminder was acted on.

CONTEXTUAL ANALYSIS · 04 / 06
STEP 04 · MOMENT

Proactive Trigger Evaluation Engine

While the app is open, it checks user-authored reminders and evaluates whether a pill reminder or wellbeing check-in is due.

TRIGGER MATCHGentle reminder
NORMAL STATECompanion mode
HONEST DELIVERY

This prototype does not send reminders when the app is closed and does not verify medication ingestion.
