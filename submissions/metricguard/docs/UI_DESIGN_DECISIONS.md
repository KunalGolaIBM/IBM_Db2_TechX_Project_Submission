# UI Design Decisions

Binding philosophy (from the project owner): refined, modern, highly readable, low text. Later contributors must keep it. Copy budget: one idea per block, no paragraph above ~3 lines, secondary text never below 12 px.

## Product framing

MetricGuard is an analytics workspace for inspecting answers, not a chat. The promise "Don't just trust the number. Verify the evidence." is the only headline. Layout is **answer on the left, evidence on the right**; there are no chat bubbles.

## Visual system

| Decision | Choice | Why |
|---|---|---|
| Surface | Warm neutral `#f6f5f2` page, white cards, 1 px hairline borders | Calm enterprise feel, no gradients or glow |
| Evidence surface | Dark `#15171b` panel, light `#0f1114` code well | Separates *execution evidence* from *interpretation*; the code reads best on dark |
| Accent | Single ink-blue `#1f5fbf` for links and focus; primary buttons are near-black | Restraint; status colors carry meaning |
| Type | Geist Sans / Geist Mono via the local `geist` package (no network fonts) | Refined, tabular numerals for money |
| Headline number | 44–56 px semibold, tabular | The answer must be readable in one second |
| Status colors | green verified, amber warnings, violet ambiguous, red blocked, orange failed. Each has an icon and a label | Never color alone; failed ≠ blocked |
| Motion | 220 ms rise-in, skeleton shimmer; both disabled under `prefers-reduced-motion` | Minimal |

## Charts (dataviz rules applied)

- Chart type comes from the backend `chart.type`: `line`, `bar` (drawn horizontal for readable category labels), `grouped_bar`. `kpi` draws **no chart**: headline plus tiles built from `result.rows[0]`.
- Fixed categorical order (blue, orange, aqua, yellow, …), color follows the series, never its rank. Single series: no legend box; 2+ series: legend. Bars ≤ 24 px with 4 px rounded data end; 2 px lines with white-ringed 8 px dots; hairline solid grid.
- Labels are selective: value at bar tip, last point on a single line; the tooltip carries the rest.
- Axis ticks compact (`$140K`); tooltips and tiles show full `$111,093.25`. RATIO is ×100. `null` renders "—", never 0.
- A Chart/Table toggle is always available (the table is the accessible alternative); the chart has a text `aria-label`.
- If the chart shows fewer metrics than the result (different unit), a note says so. Nothing is invented.

## Evidence panel

Order: verdict → **Executed SQL** → verification checks → query parameters → metric definitions → *interpretation* (plan, assumptions, planner) → timing and ids. SQL comes before the checks so it is visible on a 900 px viewport. Checks are one-line rows (details on demand; WARN/FAIL always show detail). The verdict copy is precise: "Passed every check below … It does not certify that the underlying data is correct." The panel works unchanged for live results and stored audit records (`lib/evidence-model.ts`).

Honesty rules baked into copy: the demo planner is named as not an LLM; SQL is "generated by metricguard-compiler, not by the language model"; a failed or blocked request never shows numbers; "Connected" appears only when `/api/health` says `ok`.

## Responsive and accessibility

- Two columns from 1280 px (evidence sticky), single column below. Audit table becomes cards under 768 px. Verified: no horizontal page overflow at 390, 820 and 1440 px.
- SQL scrolls inside its own box (keyboard-focusable), with a Wrap toggle. Tables scroll inside a focusable region.
- Skip link, labeled form, visible 2 px focus ring, `aria-expanded` on collapsibles, `aria-live` on results, `aria-busy` on the form, status text beside every status color.
- Duplicate submit protection: the Analyze button is replaced by Cancel while loading, repeated shortcuts are ignored, and the hook refuses a second in-flight request.

## Rejected ideas

Chat transcript layout, dashboards of fabricated KPIs, a global theme switcher, animated hero art, a percent-change badge (the API has no comparison field), confidence scores (none exist).
