## Problem Statement
* **The Core Issue:** Households frequently discard edible food because they lose track of what is already in their pantry or fridge, do not know which ingredients expire first, or struggle to find recipes that maximize the use of available leftovers.
* **Target Audience:** Busy households, eco-conscious home cooks, students, and family kitchen managers aiming to save money and curb domestic food waste.
* **Why Existing Tooling Is Insufficient:** Standard recipe search engines (Google, AllRecipes) suggest dishes based only on keywords without understanding actual pantry inventory, perishability urgency, or unit conversions. Generic LLM chatbots frequently hallucinate non-existent quantities, suggest unsafe expired items, or invent ingredients not present in the user's kitchen.

---

## Solution Overview
**EcoBite AI** solves domestic food waste using a strict, reliable two-stage hybrid architecture:
1. **IBM Db2 System of Record:** Stores canonical ingredients, household stock levels, user-entered expiry dates, structured recipes, 384-dimensional dense recipe embeddings, cooking history, and an immutable inventory event ledger.
2. **Two-Stage Hybrid Recommendation Pipeline:**
   - **Stage A (Semantic Candidate Retrieval):** Retrieves semantically relevant candidate recipes by comparing the user's natural language request vector against recipe embeddings stored in Db2.
   - **Stage B (Deterministic Waste Optimizer):** Re-ranks candidate recipes in Python using a multi-signal scoring function (coverage percentage, quantity sufficiency, urgency of items nearing expiry, and missing ingredient penalties).
3. **Grounded AI Generation:** Passes verified candidates and factual inventory to LangChain (configured with free OpenRouter models such as `meta-llama/llama-3.3-70b-instruct:free` or local deterministic fallback). Instructions are strictly validated via Pydantic to prevent hallucination.
4. **Closed-Loop Consumption:** Once the user cooks the meal, an atomic Db2 transaction deducts stock and records the event in `INVENTORY_EVENTS` and `COOKING_HISTORY`.

## IBM Db2 Integration
* **Db2 Edition & Environment:** IBM Db2 Community Edition (v12.1.0500 on Linux x86_64 via Docker) and compatible with Db2 on IBM Cloud.
* **Connector & Drivers:** Native `ibm_db` (v3.3.0) and SQLAlchemy integration (`ibm_db_sa`). Includes automated Windows DLL path resolution for `clidriver\bin` and `AUTHENTICATION=SERVER` negotiation.
* **Database Tables:**
  1. `INGREDIENTS`: Master catalogue with canonical names, categories, default units, and aliases.
  2. `USER_INVENTORY`: Household pantry stock, positive decimal quantities, storage locations, and user-entered expiry dates.
  3. `RECIPES`: Master cookbook with preparation/cooking times, servings, dietary tags, and JSON instructions.
  4. `RECIPE_INGREDIENTS`: Structured relational mappings between recipes and required ingredients with quantities and units.
  5. `RECIPE_EMBEDDINGS`: Persisted 384-dimensional dense vectors generated by Sentence-Transformers with model metadata and source text hashes.
  6. `COOKING_HISTORY`: Consumption records of prepared recipes and timestamped servings.
  7. `INVENTORY_EVENTS`: Immutable audit ledger recording stock additions, deductions (`quantity_delta`), discards, and event reasons.

## AI / LLM Architecture
* **AI Orchestration:** LangChain (`langchain-core`, `langchain-openai`).
* **Model Provider:** Configured for OpenRouter Free models (`meta-llama/llama-3.3-70b-instruct:free`), with pluggable support for OpenAI GPT-4o, watsonx.ai, Google Gemini, or a deterministic grounded generator for offline evaluation.
* **Embeddings:** HuggingFace `sentence-transformers/all-MiniLM-L6-v2` generating 384-dimensional dense vectors persisted directly in Db2.
* **Deterministic Guardrails & Pydantic Validation:**
  - The LLM never performs arithmetic, never guesses expiry dates, and cannot independently alter inventory.
  - LLM outputs are validated against `GeneratedRecipe` and `GeneratedRecipeIngredient` schemas.
  - Ingredients claimed as `source="inventory"` are cross-checked against actual Db2 stock; unsupported items are automatically reclassified to `source="additional"`.

## Setup & Installation

### 1. Clone & Navigate to Submission
```bash
git clone https://github.com/ashfinashfi/IBM_Db2_TechX_Project_Submission.git
cd IBM_Db2_TechX_Project_Submission
```

### 2. Set Up Virtual Environment & Dependencies
```bash
uv venv .venv --python 3.12
.venv\Scripts\activate          # On Windows
# or: source .venv/bin/activate  # On Linux/macOS

uv pip install -r submissions/db2-recipe-waste-optimizer/requirements.txt
```

### 3. Start IBM Db2 with Docker
```bash
docker compose -f submissions/db2-recipe-waste-optimizer/docker-compose.yml up -d
# Wait ~1-2 minutes until Db2 logs report: "(*) Setup has completed."
```

### 4. Initialize Database Schema & Seed Data
```bash
# Set Python path
$env:PYTHONPATH="submissions/db2-recipe-waste-optimizer/src"   # PowerShell
# or: export PYTHONPATH="submissions/db2-recipe-waste-optimizer/src"

# Create Db2 tables & indexes
python submissions/db2-recipe-waste-optimizer/scripts/init_db.py --drop

# Ingest curated recipes and persist 384-d embeddings in Db2
python submissions/db2-recipe-waste-optimizer/scripts/seed_recipes.py

# Seed judge benchmark demo inventory (spinach & tomato expiring tomorrow)
python submissions/db2-recipe-waste-optimizer/scripts/demo_seed.py
```

## Live Demo Script

1. **Verify Db2 Connection:** Check `http://localhost:8000/health` — reports `status: "healthy"` and `dbms_name: "DB2/LINUXX8664"`.
2. **Inspect Current Pantry:** Navigate to the Web Dashboard. Notice that Spinach (100g) and Tomato (3 pieces) are highlighted in **urgent red** (expiring in 1 day).
3. **Ask for a Meal:** In the AI Recipe Assistant tab, submit:
   > *"Suggest a quick vegetarian dinner using what I have"*
4. **Inspect Re-ranking:** Db2 retrieves candidate recipes via dense embeddings. The deterministic optimizer boosts **Spinach & Tomato Homestyle Curry** to #1 because it has 100% coverage and consumes both items expiring tomorrow.
5. **Review Grounded Recipe:** Inspect the recipe card; ingredients are cleanly categorized into *"In Your Pantry"* vs *"Additional Needed"*.
6. **Cook & Deduct Stock:** Click **"I Cooked This Meal"**. An atomic Db2 transaction updates stock levels (spinach is marked `consumed`) and records an entry in `COOKING_HISTORY`.
7. **Audit Ledger:** Open the Audit Ledger tab to verify that the deduction was persisted in the Db2 `INVENTORY_EVENTS` table.

## Known Limitations & Future Roadmap
* **Visual Ingredient Scanning:** Currently relies on structured text and manual entry; integrating multimodal image recognition for receipt and fridge photo parsing is planned for future releases.
* **Native Db2 In-Database Vector Indexing:** Storing vectors in `CLOB` with cosine distance computed in Python works with low latency for household-scale cookbooks (100s of recipes). When Db2 native vector index syntax is standardized across community editions, the query layer can shift to native vector indexes.
