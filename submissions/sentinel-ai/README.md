## Problem Statement
Defence organisations depend heavily on digital infrastructure for strategic operations, administration, intelligence, and logistics. A critical cybersecurity vector is **account compromise**, where adversaries gain unauthorized access through stolen credentials, credential stuffing, or targeted phishing.

In modern defence networks, suspicious activities such as repeated failed login attempts, successful logins from unfamiliar devices, and unusual access to classified resources often occur across different subsystems within short periods. Traditional security monitoring tools display these activities as **disconnected, individual alerts**, requiring intensive manual investigation by analysts and delaying containment of active intrusions.

---

## Solution Overview
SENTINEL AI solves this challenge through **Multi-Agent Security Event Correlation**:
- **Continuous Telemetry Monitoring:** Ingests authentication telemetry and resource queries directly from IBM Db2.
- **Velocity & Burst Detection:** Flags authentication failure bursts ($\ge 5$ failed attempts) and unusual off-hours activity.
- **Behavioral Deviation Profiling:** Detects unregistered devices (e.g. Kali Linux Workstations) and unauthorized external/foreign IP addresses.
- **MITRE ATT&CK Matrix Alignment:** Maps observed activities to standardized tactics (`T1110.001`, `T1078.002`, `T1530`, `T1021`).
- **Explainable AI Risk Scoring:** Computes an objective risk score ($0 - 100$) and generates plain-language intelligence explanations via IBM watsonx.ai.
- **Human-in-the-Loop Response Governance:** Formulates targeted defensive playbooks (`LOCK_ACCOUNT`, `REVOKE_SESSIONS`, `ISOLATE_ENDPOINT`) that strictly require administrator sign-off before execution.

## IBM Db2 Integration
- **Db2 Edition & Environment:** Db2 on Cloud / Db2 Community Edition (Docker) with high-performance local compatibility fallback.
- **Connector / Driver Used:** Python native `ibm_db` package (version 3.3.0) with parameterized SQL queries.
- **Database Schema (7 Core Tables):**
  1. `USER_ACCOUNTS`: Synthetic personnel profiles, roles, departments, and clearance levels.
  2. `LOGIN_EVENTS`: Authentication telemetry, device names, IPs, and failure reasons.
  3. `ACCESS_LOGS`: Resource queries and military classification tiers (`TOP_SECRET`, `SECRET`, `CONFIDENTIAL`).
  4. `SECURITY_ALERTS`: Telemetry anomalies flagged by the Event Monitoring Agent.
  5. `INCIDENTS`: Correlated security incidents with composite risk score and MITRE techniques.
  6. `AI_ANALYSIS`: Findings, confidence metrics, and reasoning generated by each of the 5 agents.
  7. `RESPONSE_RECOMMENDATIONS`: Proposed defensive containment actions and commander approval states.
- **Key Queries & Operations:**
  - Dynamic parameter-bound lookback queries analyzing authentication velocity.
  - Multi-table relational joins connecting incidents, user accounts, and security alerts.
  - Transaction-safe updates for human authorization audit trails.

## AI / LLM Architecture
- **Framework:** **LangGraph 1.2** with compiled linear `StateGraph`.
- **Orchestration Workflow:**
  `START` $\rightarrow$ `event_monitoring` $\rightarrow$ `behaviour_analysis` $\rightarrow$ `threat_intelligence` $\rightarrow$ `risk_assessment` $\rightarrow$ `incident_response` $\rightarrow$ `END`.
- **Model Provider & Model:** **IBM watsonx.ai** (`ibm/granite-13b-chat-v2` / `ibm/granite-3-8b-instruct`) with zero-latency deterministic explainable AI reasoning.
- **Explainable AI:** Rather than opaque black-box recommendations, the system outputs structured evidence, mathematical score breakdowns, and operational defence implications.

## Configuration

Copy `.env.example` to `.env` in `backend/` and configure your IBM credentials:

```bash
cp .env.example .env
```

```ini
# IBM Db2 Credentials (Optional: uses local resilient store if omitted)
DB2_DATABASE=BLUDB
DB2_HOSTNAME=dashdb-enterprise.services.dal.bluemix.net
DB2_PORT=50001
DB2_PROTOCOL=TCPIP
DB2_UID=your_db2_user
DB2_PWD=your_db2_password
DB2_SECURITY=SSL

# IBM watsonx.ai Credentials
WATSONX_APIKEY=your_watsonx_api_key
WATSONX_PROJECT_ID=your_project_id
WATSONX_URL=https://us-south.ml.cloud.ibm.com
WATSONX_MODEL_ID=ibm/granite-13b-chat-v2
```

## Screenshots & Demo

### 1. Section 8 Attack Simulation
Click **`Simulate Section 8 Attack`** on the dashboard. The system injects:
- 15 failed logins from foreign IP `198.51.100.77`
- 1 successful login from `KALI-INTRUDER-WORKSTATION`
- 1 unauthorized access to `DEF-TOPSECRET-WARPLAN-DELTA`

The 5 LangGraph agents correlate these events into a **CRITICAL (100/100)** incident and map them to MITRE techniques `T1110.001`, `T1078.002`, `T1530`, `T1021`.

### 2. Human Approval & Containment
Navigate to **Human Approvals**, review the `LOCK_ACCOUNT` action, enter commander notes, and click **`AUTHORIZE & EXECUTE`**. The status in `USER_ACCOUNTS` immediately updates to `LOCKED`.
