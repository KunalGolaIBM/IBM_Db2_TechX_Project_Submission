# Evaluation results

Generated by `python -m asof.eval`. Every number below comes from a recorded run in [docs/eval/](eval/); nothing is hand-edited.

- **False-allow rate**: drafts that are wrong for their date but were released as PASS, over all wrong drafts. The safety number.
- **False-block rate**: correct drafts that were rewritten or escalated, over all correct drafts.
- **Safe**: the decision was one of the case's acceptable outcomes (for a wrong draft, CORRECTED or ESCALATED; for a correct draft, PASS). **Ideal**: exactly the expected decision.
- **Citation accuracy**: the key claim was checked against the right clause version for the date.
- **Rule check flagged**: wrong drafts in which the deterministic rule check found a mismatch with `RULE_JSON` in the draft itself, whatever the judge said.
- **Rule overrides**: claims the deterministic rule check turned from the judge's SUPPORTED to CONTRADICTED.

The airline test split (40 cases) was committed in `81b5b69` before any run and is frozen: the runner refuses to run it if its SHA-256 changes. The dev split (20 cases) holds the scenarios used while building. The bank splits (Fernhollow Bank, the second fictional domain) work the same way: `bank-test` (26 cases) was committed and pinned before its first run, and `bank-dev` (12 cases) is for iterating. That first bank run found a gap in clause MTF-003's rule data, which was then fixed, so bank runs after `6d928b7` are not blind. `extractor-test` (10 cases, both documents) holds drafts that try to talk the claim extractor out of a wrong claim; it was pinned before its first run at `a7bece1`. `bank-test2` (22 new bank cases) restores a blind bank measurement: it was pinned before its first run and nothing was changed because of it. `escalation-test` (33 new cases, both documents) targets the known causes of holding a draft that could have been corrected or passed; it was pinned before its first run and before any change meant to reduce those escalations, which were tuned on `escalation-dev` (14 cases) only. `situation-test` (12 new cases, both documents) holds drafts whose premise about the customer contradicts or restates what the customer said; it was written after the change that shows the judge the question, and pinned before its first run. That run released 3 of 7 drafts whose premise contradicted the customer, which led to the situation_conflict check; `situation-test2` (12 new cases) was then pinned before its first run as the blind measure. Runs marked "(ablation: current-policy)" check every case against the policy in force on 7 Nov 2026 instead of the case's own date: AsOf's own check standing in for one that only knows the current policy, scored against the same labels.
